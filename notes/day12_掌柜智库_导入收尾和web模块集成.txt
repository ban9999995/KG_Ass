    4.2 具体内容
        fastapi定义路径:
        fastapi定义请求方式:
             @fastapi对象. 请求方式函数 get post put delete(/设置路径 {} param 请求体)
        fastapi如何接收参数: 1. 路径参数  2. param/query ?key=value 3. 请求体参数[json/文件]
             1.路径参数    动态路径 {key}  函数(key:类型 不能给默认值 路径参数必须传递)
             2.param参数  不影响路径  函数(参数key:类型=默认值)
             3.请求体json  put/post 不影响路径   定义一个类(json前端就是对象) 类型定义对应jsonkey的属性  继承BaseModel
             4.请求体文件  put/post 不影响路径 函数(key:list[UploadFile])  key.file .filename .size .content_type | async read()
        fastapi如何响应数据:
             1. json数据  dict / 继承BaseModel的类
             2. 文件    FileResponse(filename -> 加 下载 | 不加 类型浏览器能直接打开,开发,否则也会下载,path,media_type)
             3. 流式响应  StreamingResponse(生成器(),media_type="text/event_stream") [了解]
    4.3 扩展异步: 如何在fastapi接口中开启一个异步的任务
        方式1: asyncio.create_task(run_deep_agent(request.query, thread_id))  执行过程放到协程中 实现互补干扰的异步  [python 异步协程]
        方式2: fastapi提供一种更高级的方案  def(task:BackgroundTasks)
              task.add_task(函数() -> async 协程 || 没有 async -> 开一个新的线程)  线程 或者 协程
        默认fastapi接口调用机制: [宏观]
           每次请求 -> 开启线程/协程 -> 执行接口函数     [每个接口函数之间互不干扰]   [宏观]
                            接口1  线程/协程
                            接口1  线程/协程      async 加  协程(time.sleep(xx)) | 不加 线程
                            接口1  线程/协程
           解释: fastapi接口可以支持多个客户端并发访问,互相不阻塞! 每个都是'独立'
           推出: 线程模型
                fastapi
                   协程事件线程  -> event loop -> 协程  协程  协程
                   线程池       -> 线程1 线程2 线程3 线程4...  场景: def 接口  1 2 3 -> 同一个线程id
       在一个方法中,开启'异步'动作:  理解返回结果
           接口1 -> 1 -> 2 -> 3 -> 默认同步
           需求: 上传文件,进行文件切割导入向量库   接口: 1. 接收文件 2. 调用langgraph解析 20s [不阻塞/异步] 3.前端结果 [直接返回]
           方案:
             1. 开启协程 asyncio.create_task(函数) 1 [2] 3
             2. 开启线程
             3. fastapi 函数(task:BackgroundTasks)  task.add_task(2) async 2 协程 |  2 线程 -> 执行流程->   1 3 [2]

              uvicorn
                  开启新的线程/协程
                  fastapi接口(task [异步的函数])
                  task要异步函数
                  函数开启异步动作 [线程/协程]
