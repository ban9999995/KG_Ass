
1. 项目介绍
   1.1 项目导入流程
   	   任务分发: 判断文件类型,跳转到解析节点
   	   pdf解析:  判断pdf文件类型,会解析成md
   	   图片处理: 识别图片意图,进行图片的地址上传  ![](./) -> ![描述](http..)
   	   内容切割: md -> chunk 
   	   主体识别: 文件 -> 主体 -> 问题缩小范围  [1.一个文件只有一个主体 2.多个文件对应一个主体]
   	   数据向量化: chunk 主体 向量
   	   向量入库: 向量存储到向量数据库
   1.2 项目检索流程 
       用户问题的意图识别和问题重写: 1. 从用户问题从提取主体 2. 对问题进行重写  '它好不好用? 烫金机好不好用!'
       多路检索
          1. 问题向量化检索 
          2. 问题生成假设性答案检索
          3. 利用网络mcp服务进行检索
        向量查询数据融合 1 2 
        使用重排序模型进行 12 + 3路融入
        生成答案

       步骤2: 同步项目的依赖配置
          1. 导入项目依赖配置 
              pyproject.toml 
              uv.lock 
          解释: 
             pyproject.toml  1.项目信息 2.依赖包信息(python = uv add xx >= 3.11)[版本是非固定的] 3. 镜像信息
             uv.lock  作用: 锁定依赖版本  生成: 1. 第一次uv sync  第二次不改动 
                                              2. 我们主动add   uv add  uv remove 
             uv sync -> 1. 先去pyproject.toml  / dependencies 查找我们需要的依赖
                        2. 再去uv.lock查找有没有锁定对应依赖版本
                        场景1: 没有uv.lock 或者 uv.lock没有对应依赖包  下载最新版本同时生成或者再uv.lock添加版本锁
                        场景2: 有uv.lock,且锁定过版本,就下载对应的版本! (避免不同时期,同步不同的版本,项目不兼容的问题)
          2. 同步和检查依赖
             uv sync -> pyproject.toml 下载依赖 >= 3.11 -> 大于 且最新版本依赖   0318  0415 0511
             uv tree

          2. 日志工具输出级别
               日志级别: debug - info  - warning  - error - exception 
               级别好处: 1. 不同的级别输出到不同的位置 debug -> 控制台 info -> 文件 error -> 发邮件
                        2. 利用级别控制整体的开关  例如:  关闭info级别 (debug/info) 
               原则: 使用对应的输出对应的内容! 
                   debug: 类似idea开发工具的debug思路,详细输出业务的执行过程! 每行添加debug输出都不过分!! [日志输出最多]
                   info : 核心步骤输出, 1. 业务的业务入口(开始+开始核心参数) 2.关键的拐点(if)  3.业务的结束点(结束+业务的结果)
                   warning: 可能发生问题的点,已经发生问题的点,但是这个问题可以修复!不影响业务的继续进行!
                           if money > 10000: -> 某个阈值发生了偏离
                              waring(可能没有这么多钱!!)
                           local_dir rag - pdf - md -> 存储 -> local_dir 
                           if not local_dir.is_dir():
                              local_dir 存在 / 是文件夹
                              logger.warning(f"local_dir没有对应的文件夹,我们已经完成创建,业务继续进行!")
                              local_dir.mkdir(parents=True,..)
                   error: 已经发生了问题,问题不可以修复,业务提前终止...
                          rag - pdf local_file_path - md -> 存储 -> local_dir [warning]
                          if not local_file_path.is_file():
                              local_file_path没有真实的文件
                              loggger.error("xxxxx,业务无法继续了!")
                              raise FileNotFountError(f"xxxxxxxxx")  -> 异常处理的装饰器 -> 步骤 -> 润色 -> 发给前端
                   exception: python专属,可以输出错误的堆栈信息
                   		  try:
                   		  		if xxx
                   		  		   error  --> 明确错误 -> 我们自己主动raise异常和描述
                   		  except Exception as e :
                   		       发生了异常
                   		       logger.exception(xx) -> 代码的意外报错 -> 打印日志信息 -> 报错的堆栈调用信息简化输出
                   		       logger.error(xx) -> 打印日志信息 [不在这使用]
